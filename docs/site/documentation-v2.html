01 / The research question

Generation can continue.
Should judgment follow?

An agent can produce a different image at every step. That alone does not show progress.

I used a moving artwork as a test environment for this problem. Model agents edit the program, then the studio runs and records the result.

The artwork has a specific identity: simulated particles sense and deposit into a shared trail. Their local interactions produce the larger forms.

The model can change the visual expression, but the shared-trail process must remain central. This gives exploration a purpose without specifying every future image.

02 / The key decision

I removed the judge.
Not the judgment.

The early design proposed several variants and an image-only model judge. A later version added a novelty requirement and a small archive of possible parents.

The project notes describe higher costs and a mismatch with human preference. They do not establish a measured quality advantage.

I changed the policy: one child per step, kept when it passes the program checks. Human review remains separate from that technical decision.

This was a design response to the project, not a controlled result showing that one policy makes better art.

A working program and a successful artwork are two different results. The studio makes that distinction visible.

03 / What I built

A complete loop.
A visible record.

The model receives an inherited program, recent pictures, a history of changes, and the artistic brief. It edits a working copy.

The controller checks the package, publishes a fixed copy, and captures the result. That source and image remain tied to the recorded version.

The interface exposes the history instead of presenting a final image without its context.

The edit and the render have boundaries

A manifest defines editable files. The studio checks the edit against those rules before publishing the work.

The artwork loads on a separate origin, and capture modes have different isolation boundaries. A browser context is not a container or a security guarantee.

The record is part of the tool

Version history, captured images, agent activity, and recorded costs make a run inspectable. An intention can be compared with the visible result.

The record shows actions and outcomes, not a complete account of the model's reasoning.

Evidence stayed beside the work

In the judged-tree design, the interface showed the variants, their images, the author explanation, and the changed files together. These images record master-era runs.

05 / What I learned

Better tools expose
the difficult question.

The useful result was not an autonomous taste engine. It was a working environment where I could inspect the relationship between edits, pictures, and selection.

The recorded judge demonstration used a deterministic pixel-based test double. It does not provide evidence of aesthetic judgment.

The record became as important as the next output.

Evaluation needs a target.

Program validity, novelty, and aesthetic preference are different questions. A single success label should not hide those differences.

Autonomy needs evidence.

A run can continue without step-by-step approval. Its changes still need a visible history and an independent human assessment.

Less machinery can reveal more.

Removing the automatic judge made the unresolved artistic question explicit. More agents would not, by themselves, answer it.

The next experiment

Measure the disagreement.

I would compare judged selection with one-child continuation under matched starting conditions and spending limits.

Blind human comparisons, failure rates, and cost would test different outcomes separately. That controlled comparison has not been done.
